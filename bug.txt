Bug Report: mattn/postgres v0.8.5 - Incomplete Package

Issue:
------
mattn/postgres v0.8.5 fails to build due to missing C function implementation.

## Build Error:

```
Error: [4021]
    ╭─[ /home/mattn/dev/hogehogehoge/.mooncakes/mattn/postgres/postgres.mbt:91:16 ]
    │
 91 │   let result = pg_execute_internal(self, string_to_c_bytes(sql), params)
    │                ─────────┬─────────  
    │                         ╰─────────── The value identifier pg_execute_internal is unbound.
────╯
```

## Root Cause:

The mattn/postgres v0.8.5 package is **incomplete** and has mismatched files:

1. **postgres.mbt** (MoonBit source) contains:
   - `pub fn Connection::execute(self : Connection, sql : String, params : Array[Value]) -> Result[QueryResult, PgError]`
   - This method calls `pg_execute_internal(self, string_to_c_bytes(sql), params)` at line 91

2. **postgres_c.c** (C implementation) is MISSING:
   - The function `pg_execute_internal` is NOT defined
   - Only these functions exist:
     - pg_connect_internal
     - pg_query_internal
     - pg_prepare_internal
     - pg_execute_prepared_internal (for prepared statements only)
     - pg_close_statement_internal
     - pg_close_internal
     - pg_error_message
     - pg_statement_error
     - pg_ntuples
     - pg_nfields
     - pg_getvalue
     - pg_fname
     - pg_cmdtuples
     - pg_free_result
     - pg_connection_is_null
     - pg_result_is_null
     - pg_statement_is_null

## Impact:

- The `Connection::execute` method is unusable
- Direct execution with parameters is not available
- Only prepared statement execution works (via `PreparedStatement::execute`)

## Required Fix:

Add `pg_execute_internal` function to postgres_c.c that handles both direct execution
and prepared statements. The function should:
- Accept a Connection pointer, SQL bytes, and Value array
- Convert Value enum to PostgreSQL parameter format
- Call either `PQexecParams` (for direct execution) or `PQexecPrepared` (for prepared)
- Return QueryResult or NULL on error

## Additional Notes:

This appears to be a packaging/publishing error where:
- postgres.mbt was updated to add Connection::execute method
- But postgres_c.c was NOT updated to include the corresponding pg_execute_internal function
- The package was published in this incomplete state

## Workaround:

**None available**. The package is missing required implementation code.

Users must:
- Wait for mattn/postgres maintainer to release a corrected version (0.8.6 or higher)
- Use prepared statement methods instead (which do work)
- Report this issue upstream

## Root Cause:

The postgres_c.c file in mattn/postgres v0.8.3 uses 7 arguments for `PQexecPrepared`:

```c
PQexecPrepared(stmt->conn, stmt->name, param_count, (const char * const *)param_values, 
             NULL, param_lengths, param_formats, 1)
```

However, the PostgreSQL libpq library installed on this system expects only 6 arguments:

```c
extern PGresult *PQexecPrepared(PGconn *conn,
                              const char *stmtName,
                              int nParams,
                              const char * const *paramValues,
                              const int *paramLengths,
                              const int *paramFormats,
                              int resultFormat);
```

The 7th argument `(int)1` at the end should be removed, and the 4th argument should be passed as `(const char * const *)param_values` (which is already correct).

## PostgreSQL Version Information:

System libpq header file (/usr/include/postgresql/libpq-fe.h) expects:
- **6 arguments**: conn, stmtName, nParams, paramValues, paramLengths, paramFormats, resultFormat

The code uses:
- **7 arguments**: conn, stmtName, nParams, paramValues, NULL, paramLengths, paramFormats, 1
